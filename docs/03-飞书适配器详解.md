# 03 飞书适配器详解

适配器代码内嵌在
[`examples/feishu-adapter.yaml`](../examples/feishu-adapter.yaml) 的 ConfigMap
（`adapter.py`，约 470 行），Deployment 以 `python:3.12-alpine` 直接运行它，
**零第三方依赖**。Alertmanager webhook → 飞书自定义机器人的所有翻译工作都在这里。

## 1. 部署形态

```text
Alertmanager --POST /alerts (JSON)--> Service:8080 --> Deployment (2 副本)
                                                          │ 环境变量：
                                                          │  FEISHU_WEBHOOK_URL   ← Secret feishu-gpu-alerts/webhook-url
                                                          │  FEISHU_SIGNING_SECRET← Secret feishu-gpu-alerts/signing-secret（可选）
                                                          │  PROMETHEUS_URL       ← 集群内 Prometheus（发送时快照/接续提示用）
                                                          ↓
                                                     POST 飞书 webhook（text 消息 + 签名）
```

安全加固：非 root（runAsUser 10001）、只读根文件系统、drop ALL capabilities、
`securityContext` 全套；webhook 地址与签名密钥只通过 Secret 注入。双副本无状态，
水平扩展即可。

## 2. 请求处理流程（`Handler.do_POST`）

```python
POST /alerts            # 其他路径 404
  → 读取 body（上限 1MB）
  → build_message(event)          # Alertmanager JSON → 中文文本
  → feishu_payload(message)       # 包一层 msg_type=text + 可选签名
  → POST 飞书 webhook             # 10s 超时
  → 飞书返回 code != 0 视为失败 → HTTP 502，Alertmanager 会重试
```

返回语义：`200` 成功、`400` 请求体非法、`502` 飞书投递失败（Alertmanager 会按
groupInterval 重试）、`500` 其他异常。日志只打请求行与错误，不打印 Secret。

## 3. build_message：JSON → 中文文本

主要构件：

| 构件 | 作用 |
| --- | --- |
| `ALERT_NAMES` | 告警代码 → 中文名（如 `GPUStackModelInstanceLoaded` → "GPUStack 模型实例已加载"） |
| `STATUS_NAMES` / `SEVERITY_NAMES` / `CATEGORY_NAMES` / `EVENT_NAMES` | firing/resolved、严重级别、类别、事件（allocated→资源已分配 等）四张翻译表 |
| `alert_title(name, status)` | 单条标题；生命周期告警带 🟢/🔴 图标 |
| `lifecycle_header(name, alerts, status)` | **消息首行横幅**（见下） |
| `lifecycle_summary(name, status, labels)` | 生命周期摘要："用户 X 的任务进程 Y 已开始运行/已结束" |
| `lifecycle_continuation(name, status, labels)` | **接续提示**（见下） |
| `resource_snapshot(labels)` | 按节点+GPU 并发查 8 条 PromQL，拼出"资源余量（发送时）"段落 |
| `beijing_time()` / `format_duration()` | 事件时间转北京时间、时长人性化（"1 小时 20 分钟"） |

### 3.1 消息骨架

```text
【横幅】标题                       ← lifecycle_header
集群：{cluster 或 gpustack-rke2}

1. {单条标题}                      ← 每条告警一段，最多展开 MAX_ALERTS=20 条
状态：已触发/已恢复 | 级别：…
告警代码：…
类别：…
节点/命名空间/Pod/GPU/进程/PID/模型/负责人/团队/项目/任务…
事件：{EVENT_NAMES 翻译}
摘要/详情
触发时间（北京时间）：…
恢复时间（北京时间）：…            ← 仅 resolved
进程启动时间（北京时间）：…        ← 有 process_start_unix 时
进程运行时长：…
提示：…（接续提示，仅生命周期 resolved）
资源余量（发送时）：…              ← 同节点同 GPU 只查一次（snapshots 去重）

另有 N 条告警未展开                ← 超过 20 条时
```

整条消息上限 `MAX_MESSAGE_CHARS = 28000`（飞书 text 消息约 28k 字符上限）。

### 3.2 生命周期横幅：lifecycle_header

开始/结束消息几乎同时到达时，只看首行就能分清本条是什么：

```python
def lifecycle_header(name, alerts, status):
    statuses = [str(alert.get("status", status)).upper() for alert in alerts or []]
    if name == "GPUProcessStarted" and statuses:
        if all(s == "FIRING" for s in statuses):
            return "【GPU 任务·开始 🟢】GPU 任务进程已开始"
        if all(s == "RESOLVED" for s in statuses):
            return "【GPU 任务·结束 🔴】GPU 任务进程已结束"
        return "【GPU 任务·切换 🔄】GPU 任务进程已结束并已开始新进程"
    return f"【GPU 告警·{translated(STATUS_NAMES, status)}】{alert_title(name, status)}"
```

要点：横幅依据**组内每条告警的实际状态**而不是 webhook 顶层 `status` 字段——
Alertmanager 对混合组（旧 resolved + 新 firing，常见于 PID 复用）顶层只会报
`firing`，若直接信它会打出"已开始"却包含结束条目。混合组显示 🔄 切换横幅，
每个条目再用 🟢/🔴 标注。

### 3.3 接续提示：lifecycle_continuation

任务 A 结束后立刻启动任务 B 时，两条消息几乎同时到达、任务名相同。适配器在渲染
**resolved** 消息时实时查一次 Prometheus：

```promql
group by (pid) (gpu_process_used_memory_mib{scope="host", node="…", task="…"})
```

若存在与"已结束 PID"不同的存活进程，追加一行：

```text
提示：同任务已有新进程 PID 9500 正在运行，本条"已结束"对应上一个进程（PID 9464）；
紧随其后的"已开始"通知属于新进程，两条消息请以 PID 区分。
```

实现细节：

- 只对 `GPUProcessStarted` 且 `RESOLVED` 生效，其余告警零开销；
- 查询失败（网络/Prometheus 不可用）静默返回空串，**消息照发**，不阻断告警链路；
- 用 `json.dumps()` 转义 node/task 标签值，防止任务名含引号破坏 PromQL。

## 4. 飞书签名算法（`feishu_payload`）

启用签名校验时，自定义机器人要求附加 `timestamp` 与 `sign`：

```python
timestamp = str(int(time.time()))
string_to_sign = f"{timestamp}\n{secret}"
sign = base64.b64encode(
    hmac.new(string_to_sign.encode("utf-8"), b"", hashlib.sha256).digest()
).decode("ascii")
```

注意两点：HMAC 的 key 是 `"{timestamp}\n{secret}"`（飞书的特殊约定），消息体为空；
时间戳与飞书服务器偏差过大会返回签名错误，Pod 时区/时钟需正确。

## 5. 本地测试

适配器是纯函数式渲染，`build_message(event)` 可以脱离集群测试。把 ConfigMap 里的
`adapter.py` 抽出来，mock 掉 `prometheus_result` 即可覆盖全部消息分支：

```python
import importlib.util, yaml

docs = list(yaml.safe_load_all(open("examples/feishu-adapter.yaml")))
open("/tmp/adapter.py", "w").write(docs[0]["data"]["adapter.py"])

spec = importlib.util.spec_from_file_location("adapter", "/tmp/adapter.py")
adapter = importlib.util.module_from_spec(spec)
spec.loader.exec_module(adapter)

adapter.prometheus_result = lambda q: [{"metric": {"pid": "9500"}}]  # mock 接续查询
print(adapter.build_message({  # 模拟 Alertmanager webhook body
    "status": "resolved",
    "commonLabels": {"alertname": "GPUProcessStarted"},
    "alerts": [{
        "status": "resolved",
        "labels": {"node": "gpu-node-15", "task": "train.py", "pid": "9464",
                   "owner": "25_wb", "process_start_unix": "1791698991"},
        "annotations": {"summary": "…"},
        "startsAt": "2026-10-11T07:00:00Z", "endsAt": "2026-10-11T07:30:00Z",
    }],
}))
```

建议覆盖的用例：纯 firing、纯 resolved（有/无接续）、resolved+firing 混合组、
非生命周期告警（格式不变）、Prometheus 查询失败（降级不阻断）。

## 6. 常见改造点

| 需求 | 改哪里 |
| --- | --- |
| 换企微/钉钉 | `feishu_payload`+`post_to_feishu` 换成对应机器人的报文与地址，其余不动 |
| 消息用富文本卡片 | 把 `msg_type: text` 换成 `interactive` 卡片 JSON，`build_message` 输出改为 markdown |
| 只想收 critical | 改 `alertmanagerconfig-feishu.yaml` 根路由 matchers，加 `severity=critical` |
| 调整节流节奏 | 同文件：生命周期子路由 `groupInterval/repeatInterval`，普通告警根路由 `groupWait/repeatInterval` |
| 新告警的中文名 | `ALERT_NAMES` 加一行；不带 `category` 标签的告警不会进飞书 |
